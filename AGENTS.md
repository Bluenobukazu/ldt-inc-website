## Start with the actual source
- Confirm repository, branch, exact HEAD, worktree status, task scope and affected files before changes. Never assume `main` or an old screenshot is the active approved site. Preserve unrelated work.
- Obtain the current approved LDT design grammar, page-specific locks, visual references, user decisions and release rules from provided authoritative context. The detailed `LDT_INC_EXPERIENCE_LAB` Claude files and its `qa/gate` scripts are **not part of this repository**: do not claim they are loaded or available in Codex.
- If a required decision, reference, QA prerequisite or approval is unavailable, report the precise gap as **NOT VERIFIED**. Do not invent rules, fill in lost copy, or infer approval from a technically passing test.

## Scope and design integrity
- Preserve the approved black/white editorial LDT INC system, typography, copy, navigation/hash routing, motion intent, page-specific locked content and responsive behavior. Do not silently redesign, delete copy, replace approved assets, flatten intentional animation, or add shadows/beige/3D effects.
- Reuse existing implementation and tools. Keep feature edits limited to the requested scope; do not modify UPU, personal Notion OS or another repository.
- Treat performance, source protection, accessibility, design reference comparisons, browser QA and comprehension/evaluation cases as six **task-dependent capabilities**, not six packages that must be installed. Prefer already available browser tooling; inspect actual rendered behavior, responsive views, keyboard and reduced-motion paths whenever affected. Missing browser access is NOT VERIFIED, not PASS.

## Execute, verify, hand over
- Short task contract: **Goal / Scope / Acceptance / Inputs / Mode (IMPLEMENT → VERIFY → REPORT → STOP or READ-ONLY) / Constraints**. Infer omissions conservatively; ask only for a material missing authorization or decision.
- Implement the smallest complete authorized change, inspect actual output, run proportional targeted checks, and perform no more than two in-scope correction rounds before reporting unresolved issues. Do not weaken test assertions to manufacture a PASS.
- Report PASS, FAIL, NOT VERIFIED or NOT APPLICABLE with evidence for exactly the affected revision and viewports. Keep technical QA distinct from owner aesthetic acceptance and release approval.
- Use isolated working branches/worktrees when shared Git state could conflict. No secret leakage, credential disclosure, package or MCP installation, global permission edits, commits, pushes, merges, Vercel promotion, deployment, external publication or sends without explicit **action-specific** owner authorization.
- Handover only: changed files and revision; what was reused; tests/evidence and limitations; owner approvals needed; one next action if genuinely blocked. No speculative redesign or repeated tool audits.

**Portability:** These rules are inherited only when Codex actually checks out a revision containing this `AGENTS.md`. They do not synchronize into Claude Code, ChatGPT, unrelated repos or stale Codex Cloud environments.
